MoonBit · a document library

Read the web.
Query it like a tree.

moonxml parses HTML the way a browser does — repairing as it goes — and XML the way a validator does, then hands you one mutable tree to walk, query and rewrite.

HTML· XML· SVG· one tree· CSS & XPath· Apache-2.0

listing i — tour.mbt

let page = @html.loads("<ul id=list><li>one<li>two</ul>")

// two list items, though the document closed none
page.css("li").length()          // 2

// the chain goes on: css, xpath, your own selectors
page.css("#list").xpath(".//li[2]")
    .set_text("two, edited")

// and back out, repaired, as HTML
page.dumps()

Ithe tree

One tree, two syntaxes

HTML is not well-formed and never has been; XML is and must be. Both become the same node kinds, so the query you wrote for a page works on a feed — the node does not remember which parser made it.

node kinds

pub(all) enum Node {
  ElementNode(Element)
  TextNode(String)
  CDataNode(String)
  CommentNode(String)
  ProcessingInstructionNode(…)
  DoctypeNode(String)
}

element

pub struct Element {
  name      : String            // {uri}local
  attrs     : Array[(String, String)]
  children : Array[Node]
  ...
}

Names are James Clark spelled — {urn:a}entry, not a:entry — so a node means the same thing whichever prefix the document chose.

IIthe chain

The chain never breaks

Every query narrows the nodes you have and answers the same shape, so a chain can mix engines and still land on a node you can edit.

listing ii — one selection, narrowed

1page.xpath("//table")          1 · xpath
2    .css("tr:nth-child(2)")    2 · css
3    .selector("mine", "")        3 · a selector you registered
4    .custom(@moonxml.SelectorFn::new(by_price))
5    .items[0]                  5 · a node, not a selection
6    .children()[1]             6 · walk down, one node
7    .css("span")               7 · and query again
8    .add_class("picked")        8 · edit in place

CSS

Type, class, id, attributes with every operator and the case flag, four combinators, :not/:is/:where/:has, the structural pseudo-classes, an+b.

XPath 1.0

All thirteen axes, node tests, predicates with expressions, the operator table, the core functions — and typed answers: nodes, strings, numbers, booleans.

Yours

Implement Selector, register it by name, call it in the chain like a built-in. SelectorFn covers the ones that are just a closure.

IVthe reading

Two ways to read a document

Build the tree, or do not build it at all. The XML scanner emits events to any sink, which is how the tree builder itself works — one parser, and no drift between it and a second one written for streaming.

Plate I — the reading of a document, from text to tree

A caller who only wants to count tags writes one Sink and never allocates a node.

Vthe limits

Small, and stated plainly

Two dependencies

moonbitlang/core and nothing else. No transitive surprises in your lockfile.

Fails loudly, once

One error family, Refused: a broken XML document names the byte, a bad selector names the fault. HTML never refuses — it repairs, and says what it repaired.

Four backends

wasm, wasm-gc, js and native, tested on all of them, because a parser moves bytes and bytes are where backends differ.
